# 深模組設計詞彙與改善流水線共用規則

本檔案為 `umbra-improve` 工作流（分析 → 藍圖演進 → TDD → 實施 → 雙軸審查）所有代理的**唯一詞彙與規則來源**。使用這些術語時**逐字使用**，不得改稱 component / service / API / boundary。

## 一、設計詞彙 (Glossary)

- **Module (模組)**：任何有 interface 與 implementation 的東西。刻意與尺度無關：函式、類別、套件、跨層切片皆可。
- **Interface (接口)**：呼叫者為正確使用模組所必須知道的一切——型別簽名、不變量、順序約束、錯誤模式、必要設定、效能特性。不只是型別層表面。
- **Implementation (實作)**：模組內部的程式本體。與 Adapter 不同：可以有「小 adapter 大實作」（如 Postgres repo）或「大 adapter 小實作」（如 in-memory fake）。
- **Depth (深度)**：接口上的槓桿——呼叫者（或測試）每學習一單位接口能驅動多少行為。小接口 + 大量實作 = **deep**；接口幾乎與實作等複雜 = **shallow**（避免）。
- **Seam (接縫)**：不改程式碼就能改變行為的位置，即模組 interface 所在之處。Seam 放哪與 Seam 後面放什麼是兩個獨立決策。
- **Adapter (配接器)**：在 seam 上滿足某 interface 的具體物。描述角色而非內容物。
- **Leverage (槓桿)**：呼叫者從深度得到的好處——一份實作跨 N 個呼叫點與 M 個測試回收。
- **Locality (局部性)**：維護者從深度得到的好處——變更、臭蟲、知識、驗證集中於一處。修一次，到處好。

## 二、核心原則

1. **刪除測試 (Deletion Test)**：想像刪掉此模組。複雜度憑空消失 = 它只是 pass-through，該刪；複雜度重新出現在 N 個呼叫方 = 它有在賺。
2. **接口即測試面 (The interface is the test surface)**：呼叫者與測試跨越同一道 seam。若必須測「接口之後」的東西，模組形狀可能錯了。
3. **一個 adapter 是假想 seam，兩個才是真 seam**：沒有實際變異跨過 seam 就不要造 seam。
4. **可測性三式**：注入依賴而非自建；回傳結果而非產生副作用；接口表面積小（方法少 = 測試少，參數簡單 = 佈置簡單）。

## 三、TDD 規則 (Red → Green)

- **Red before Green**：先寫失敗測試，再寫剛好能過的最小實作。禁止預寫未來測試或投機功能。
- **一次一條縱切 (Vertical slice)**：一道 seam → 一個測試 → 一個最小實作，循環前進。禁止水平切片（先寫完全部測試再寫全部實作）。
- **只在預先同意的 seam 寫測試**：測試驗證公開接口的行為，不驗證實作細節；程式整個重寫時好測試不該壞。
- **重構不屬於紅綠循環**：重構歸審查階段，不歸實作循環。

### 測試反模式（出現即退回）

- **Implementation-coupled**：mock 內部協作者、測私有方法、繞側道驗證（直接查 DB 而非走接口）。跡象：重構沒改行為但測試壞了。
- **Tautological**：斷言用與程式相同的方式重算期望值，構造上永遠通過。期望值必須來自獨立真理來源（已知字面量、手算範例、規格書）。
- **Horizontal slicing**：見上。

## 四、氣味基線 (Smell Baseline) — 兩軸審查之 Standards 軸固定底線

專案文件化規範**永遠覆蓋**此基線；基線氣味一律是**判斷題**而非硬違規；工具已強制的事項跳過。格式：氣味 → 修法。

| 氣味 | 一句話判據 → 修法 |
| --- | --- |
| Mysterious Name | 名字不揭示用途 → 改名；想不出誠實名字 = 設計混濁 |
| Duplicated Code | 相同邏輯形狀出現在多處 → 抽出共用形狀 |
| Feature Envy | 方法摸別人資料多於自己的 → 把方法搬到它羨慕的資料上 |
| Data Clumps | 同幾個欄位/參數總是一起到處旅行 → 收成一個型別傳遞 |
| Primitive Obsession | 原生型別/字串充當領域概念 → 給概念一個小型別 |
| Repeated Switches | 同一型別的 switch/if 串在多處重複 → 多型，或一張兩處共享的表 |
| Shotgun Surgery | 一個邏輯變更逼著散彈式改很多檔 → 把同變同改的收進一個模組 |
| Divergent Change | 一個模組因多種無關理由被改 → 拆開，一模組一理由 |
| Speculative Generality | 為規格外的需求加抽象/參數/掛鉤 → 刪，內聯回來等真需求 |
| Message Chains | `a.b().c().d()` 長導航 → 把這段路藏進第一個物件的一個方法 |
| Middle Man | 類別/函式大多只是轉手 → 砍掉直接叫真目標 |
| Refused Bequest | 子類忽略或覆寫大部分繼承物 → 丟繼承，改組合 |
